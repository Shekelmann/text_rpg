# Общая система эффектов

Игрок и враг используют `StatusEffect` и `EffectCollection` из `effects.py`.
`effect_type` различает `buff` и `debuff`; название и описание нужны только
для отображения. Конкретный класс определяет механику.

## Применение

`actor.apply_effect(effect)` — общий вход для мгновенных и длительных эффектов.
Возвращает `EffectResult` с сообщениями, фактическими изменениями ресурсов
и, при необходимости, прибавкой ОД. Вызывающая сторона передаёт сообщения
в журнал. Контроллер текущего хода применяет `action_points_gain` к своему
`PlayerTurnState`; прибавка не записывается в постоянные характеристики.

`actor.add_effect(effect)` сохранён для существующего кода аффиксов и DoT.
Для длительного эффекта он возвращает активный экземпляр после объединения.
Для мгновенного делегирует в `apply_effect`. Непосредственный
`effects.add(effect)` предназначен только для длительных эффектов.

При каждом независимом наложении нужен новый экземпляр эффекта.
Заклинания копируют определения перед применением; аффиксы создают новый
экземпляр через существующую фабрику.

## Время срабатывания и повторное наложение

- `Heal` и `GainActionPoint`: мгновенно, без записи в активные статусы.
- `Poison`: начало хода, сила X, затем X−1. Повторное наложение складывает
  силу только для одинакового типа урона.
- `Bleeding`: после атакующего действия, включая промах; расходует один
  оставшийся триггер. Независимые наложения остаются независимыми.
- `PhysicalShield`: меняет оставшийся после брони входящий Physical hit, истекает
  в начале следующего хода владельца. Повторное наложение обновляет щит,
  но не складывает проценты. Astral и урон с обходом защиты не уменьшает.
- `Stun`: в начале хода возвращает `skip_turn` и снимается. Два наложения
  не создают два пропуска. Остальные эффекты начала хода продолжают работать.

Существующая `Regeneration` сохранена для совместимости, без добавления
в игровой пул. Общая точка `on_turn_end` вызывается для обоих участников;
существующие DoT туда не перенесены.

## Коллекция и интерфейс

`active` возвращает активные экземпляры, `get(id)` находит первый,
`remove(instance)` снимает конкретный экземпляр. Повторное `add` обновляет
стаки или длительность по правилам самого эффекта; обработчики событий
уменьшают соответствующий счётчик и удаляют истёкшие эффекты. Единого
счётчика длительности для щита, яда и кровотечения намеренно нет.

`effects_snapshot(actor)` формирует одинаковые данные для обоих участников:
идентификатор, buff/debuff, значок, описание и текущие числовые параметры.
UI размещает их под HP; мгновенные эффекты туда не попадают.
`EnemyIntent` остаётся независимой общей категорией действия.

«Иссушение» больше не входит в Effect-систему и не является DoT. Оно
реализовано как мгновенная активная способность Глашатая в `ability.py`.

Числовые поля старых определений заклинаний `healing` и `action_points_gain`
поддерживаются через `resolved_effects`. Текущий игровой реестр использует
непосредственно `Heal` и `GainActionPoint`.

# Axe and Sword

Текстовая RPG с отдельным оконным интерфейсом на Tkinter.

## Запуск

Нужен Python 3.9 или новее с Tkinter (входит в обычный установщик Python для Windows).
Дополнительные библиотеки не требуются.

- **Windows, без CMD:** дважды нажмите `Axe and Sword.pyw`. Файлы `.pyw`
  должны быть связаны с Python / Python Launcher при установке Python.
- **Оконный режим из терминала:** `python main.py` или `python gui.py`.
- **Прежний консольный режим:** `python main.py --cli`.

## Управление

Слева находится постоянная панель управления: инвентарь, персонаж,
карта, лут-фильтр и выход. Справа — обновляемая карточка героя с HP/MP, уровнем,
бронёй, уроном, золотом, опытом и заполнением рюкзака.
В центре — текущий экран локации, меню или боя; под ним — контекстные действия.
Кнопки передают игре те же номера, что и консольный ввод. Постоянного поля Enter
нет: оно появляется только для имени и других текстовых запросов. Числовые настройки
используют счётчик, выбор нескольких значений — флажки. Консольный режим сохранён.
Имя героя можно изменить в поле ввода; кнопка «Начать игру» позволяет оставить
имя «Герой» и начать полностью мышью.

Подтверждения покупки/продажи имеют кнопки «Да» и «Нет», паузы — «Продолжить».
Лут-фильтр поддерживает флажки для нескольких значений и числовой счётчик.
Длинные списки действий прокручиваются. Центральный экран заменяется при переходе
между меню. В бою состояние противника и единственная область боевого лога
обновляются на месте. Возврат из инвентаря и снятие оружия не требуют лишнего Enter
в GUI; значимые результаты боя и сундука сохраняют кнопку «Продолжить».
ANSI-цвета предметов и противников преобразуются в цвета текста. Все панели и
элементы управления тёмные, рамки имеют лёгкую процедурную текстуру без внешних
картинок и дополнительных зависимостей.

Просмотр персонажа и карты доступен во время ожидания ввода, включая
бой, и не расходует ход. Возврат из просмотра восстанавливает текущий экран и ввод.
Кнопка «Изменить экипировку» открывает существующий инвентарь, а «Переместиться»
на карте — существующий выбор пути. Эти действия доступны на экране локации.
Во вложенных меню и бою глобальные действия, изменяющие состояние, недоступны:
используйте контекстные кнопки и «Назад», как в обычном игровом меню.

Инвентарь при первом открытии центрируется на центральном игровом поле.
Перемещение за заголовок сохраняет позицию относительно игрового окна в памяти
текущего сеанса. Повторное открытие её восстанавливает с ограничением границами
приложения; обновления предметов позицию не меняют. После перезапуска игры позиция
снова выбирается автоматически. Tooltip «Сортировать» описывает фактический порядок.

Экран «Персонаж» содержит характеристики слева и текущую экипировку справа.
Отдельного меню экипировки нет. Кольцо I, кольцо II, амулет и пояс — будущие слоты
без игровых эффектов; новых слотов обуви не добавлено. Оружие использует готовые
иконки, для брони без ассета остаётся текст и tooltip.

Над контекстными действиями расположены четыре будущих слота навыков/магии и два
слота HP/MP Flask с векторными пиктограммами. Системы фласок в текущем Player нет:
количество показано как «×—», восстановление не выдумывается, нажатия ничего не
расходуют. Существующие зелья инвентаря не преобразуются во фласки. Для подключения
в `gui_views.flask_snapshot` предусмотрено чтение `player.flasks["hp"/"mp"].count`
и `.restore_amount`; GUI не хранит отдельный запас. Общий tooltip появляется через
секунду и скрывается при уходе курсора.

Изображения врагов отображаются в размере 256×256 (целочисленное увеличение Tk,
без сглаживания). Перерисовка HP не переключает масштаб. Под изображение выделено
постоянное место; минимальная высота окна 880 пикселей обеспечивает место также
для боевого лога, навыков и контекстных действий.

Лут-фильтр **показывает выбранные** редкости/типы и предметы с минимумом N выбранных
аффиксов. Разделы применяются одновременно; пустой выбор не ограничивает раздел,
легендарные предметы всегда видны. Пояснения добавлены в существующие меню, без
изменения правил фильтра или выпадения добычи.

## Устройство интерфейса

`game_io.py` — граница ввода/вывода. В консольном режиме она вызывает стандартные
`input` / `print` и очистку терминала. В оконном режиме `DesktopIO` из `gui.py`
передаёт текст и запросы в Tk через очередь. Последовательный игровой цикл работает
в отдельном потоке; Tk обновляется только в главном потоке. Глобальная подмена
`builtins` и перенаправление общего stdout не используются.

`gui_views.py` формирует снимки данных только для чтения на игровом потоке.
В Tk передаются строки, числа и коллекции, а не объекты Player/World.
`present()` добавляет структурированные экраны локации и боя; консольные
функции отображения остаются запасным вариантом, когда GUI не подключён.

Игровые системы и обработчики действий остаются существующими. Кнопки строятся
по текущим строкам меню вида `1. Действие` и `1 - Действие`, в том числе внутри
ASCII-панелей. Очистка экрана и каждый запрос ввода отделяют новый набор действий
от предыдущего. Подтверждения и специальные поля имеют явные метаданные.

При добавлении меню с новым форматом используйте
`game_io.input(prompt, choices=(("1", "Действие"), ("0", "Назад")))`.
Для специальных запросов доступны `kind="text"`, `"pause"`, `"multiple"` и
`"number"`, а также `default`. `kind="location"` отмечает основное меню,
а `kind="return"` пропускает только служебную паузу возврата в GUI, сохраняя
обычный Enter в терминале. Это метаданные представления; обработка возвращённой
строки и все игровые правила остаются в существующих системах.

Закрытие окна освобождает ожидающий ввод и останавливает игру на ближайшей операции
ввода/вывода. Сохранение игры на диск эта версия не добавляет.

## Проверка

`python -B -m unittest discover`

Тесты включают прежнюю игровую логику, изоляцию ввода/вывода и интеграционные
сценарии с настоящими виджетами Tk: создание героя, меню, экипировка, торговля,
лут-фильтр, бой, зелья, повышение уровня, сундук и подбор предметов, обновление
карточки, отсутствие повторов боевого лога и возврат без служебных пауз.
Тестам окна нужен доступный графический дисплей; в среде без него они пропускаются.

## Заклинания

Кнопка **«Книга заклинаний»** открывает перетаскиваемое окно с визуально выделенной
активной вкладкой **«Постоянные»** или **«Одноразовые»**. Книга показывает описание,
цель, стоимость, урон и эффекты. Изученные заклинания и свитки хранятся раздельно;
свиток удаляется только после успешного применения.

В бою заклинания доступны отдельным действием. Оно расходуется один раз за ход после
успешного применения. Проверка MP и цели выполняется до списания ресурса. Прямой урон
проходит через обычный `take_damage`, а баффы и дебаффы — через `EffectCollection`.
Стартовый тестовый набор всех классов: **«Астральная искра»**, **«Ядовитая метка»**
и **«Обновление»**. Каталог находится в `spells.py`; владение и правила применения —
в `spell.py`, без состояния GUI.

# Базовые аффиксы оружия

`Item.rarity` использует существующий `Rarity`, вынесенный в `rarity.py`.
Импорт `from weapon import Rarity` остаётся совместимым.

`Affix` содержит `id`, отображаемое `name`, `type`, положительный `tier`
и неизменяемые последовательности `modifiers` и `effects`, а также
`description` для UI. Тир обозначает версию:
силу задают её модификаторы, автоматического множителя тира нет.
Шкала тиров и зависимость от уровня не заданы.
ID версии уникален в пуле и на предмете; имена и описания не участвуют в расчётах.

Поддерживаемые оружием цели:

- `physical_damage`: изменяет обе границы урона физического оружия.
- `crit_chance`: изменяет шанс критического удара оружия.
- `dodge_chance`: изменяет уклонение владельца экипированного оружия.
- `attack_physical_damage`: изменяет физический урон после прибавления силы.

Формула: `(base + сумма FLAT) * (1 + сумма PERCENT / 100)`.
`PERCENT=20` означает +20%. Для шанса крита `FLAT=0.05` означает
пять процентных пунктов. Урон округляется вниз до целого и ограничен
нулём, шанс крита ограничен диапазоном 0–1. Существующий предел крита
персонажа применяется затем, как и раньше. Бонусы характеристик персонажа
прибавляются после расчёта оружия. `physical_damage` их не масштабирует,
а `attack_physical_damage` («Берсерка») применяется затем, перед критом.
Уклонение рассчитывается от ловкости с относительными процентными
модификаторами, затем ограничивается существующим пределом 30%.

`min_damage`, `max_damage`, `crit_chance` остаются базовыми значениями.
Меню использует вычисляемые `final_min_damage`, `final_max_damage`,
`final_crit_chance` без условных бонусов. Бой передаёт владельца и цель
в `get_damage_range(source, defender)` непосредственно перед атакой.
`set_affixes`, `add_affix`, `remove_affix` сразу меняют
результат без изменения базы. Коллекция доступна как неизменяемый кортеж.

Генерация вызывается явно с доступным пулом готовых версий:

```python
from affix import Affix, AffixType, Modifier, ModifierOperation
from damage import Damage_type
from weapon import Weapon, Rarity

# Только временный пример, не финальный дизайн.
pool = (
    Affix("demo_flat", "Пробный", AffixType.PREFIX, 1,
          (Modifier("physical_damage", ModifierOperation.FLAT, 5),)),
    Affix("demo_percent", "Пробы", AffixType.SUFFIX, 1,
          (Modifier("physical_damage", ModifierOperation.PERCENT, 20),)),
)
weapon = Weapon("Меч", 10, 10, 0.1, "Одноручное",
                Damage_type.PHYSICAL, rarity=Rarity.RARE)
weapon.generate_affixes(pool)  # Принимает также rng=random.Random(seed).
```

Генератор выбирает количество COMMON 0–1, RARE 1–2, EPIC 3–4,
затем доступный тип и аффикс без повторов, максимум два каждого типа.
Готовые версии выбираются без весов и балансировки тиров.
При недостаточном пуле возникает `ValueError`; прежние аффиксы оружия
сохраняются. MAGIC и LEGENDARY не поддерживаются генератором.

Ручное назначение проверяет максимум редкости и лимит 2 + 2.
Минимум проверяется генерацией, а не ручным удалением: можно снять все
аффиксы, в том числе с Epic. Удаление или смена экипировки не оставляет
бонусов у персонажа. Копирование шаблона через `create_item` сохраняет
редкость и аффиксы с независимой заменой коллекции.

Первый игровой тестовый пул из десяти аффиксов находится в
`affix_pool.py` (`WEAPON_AFFIX_POOL`). Все версии помечены tier=1;
это не финальная шкала тиров. `generate_starting_weapons(rng=None)` создаёт
три независимых оружия из `WEAPONS` со случайными COMMON/RARE/EPIC
и вызывает существующий генератор с новым пулом. `start_game` добавляет
их в инвентарь. Обычный лут и магазин используют прежнее создание предметов.

Условия `Condition` хранят тип проверки и порог. Порог HP строгий:
ровно 20% у цели и ровно 30% у игрока не активируют соответствующий бонус.
Проверки статусов учитывают только неистёкшие Poison/Bleeding.
При отсутствии контекста условный модификатор неактивен.

Определения `OnHitEffect` создают отдельный экземпляр статуса на каждое
попадание. `Weapon.on_hit(target, successful=False)` ничего не накладывает.
Сейчас атаки игрока всегда попадают; `player_turn` вызывает `on_hit` после
прямого урона. Сам `Player.attack(target)` только рассчитывает атаку.
Новый статус не усиливает попадание, которое его наложило.
Poison(2) и Bleeding(2, 2) используют существующую систему эффектов:
яд суммируется, кровотечения действуют отдельными экземплярами.
Кровотечение тратит срабатывания только на атакующие действия цели.
Урон этих префиксов фиксированный и не масштабируется интеллектом.

`Weapon.display_name` собирает префиксы, базовое имя и суффиксы,
не изменяя `name`. Список оружия и карточка показывают описания аффиксов.
Старый минимальный пул в `test_affixes.py` остаётся тестовой фикстурой;
игровой пул и его интеграция проверяются в `test_weapon_affix_pool.py`.
